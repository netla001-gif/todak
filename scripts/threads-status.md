# Threads 연동 확인 기록

2026-09-06 확인. 실행: `node --env-file=.env.local scripts/threads-probe.mjs`

- 기존 `.env.local`의 `THREADS_ACCESS_TOKEN` 사용. 토큰과 API 페이지 URL은 출력하지 않는다.
- 계정 조회와 토큰 진단 성공. 토큰은 유효하고 `threads_keyword_search`, `threads_read_replies` 권한이 포함되어 있다.
- 첫 실행에서 검색 3건이 HTTP 500/code 1로 실패했다. 최소 필드 검색은 HTTP 200/0건이었다.
- 스크립트에 토큰 권한 진단과 검색 필드 축소 재시도를 추가했다.
- 보완 후 실행에서는 원래 필드로도 ‘아이랑’, ‘하남’, ‘Threads’ 모두 HTTP 200/0건이었다. 따라서 최초 오류를 특정 필드 문제로 단정할 수 없다.
- 다른 작성자의 게시물을 확보하지 못해 댓글 조회는 미검증이다. 검색 0건은 공개 게시물 접근 가능 여부를 입증하지 않는다.

## Meta 대시보드 확인

2026-09-06 브라우저에서 todak 앱 설정을 직접 확인했다. 외부 설정은 변경하지 않았다.

- `threads_basic`, `threads_keyword_search`, `threads_read_replies`는 모두 ‘테스트 준비 완료’로 표시된다. 고급 액세스 승인 표시는 확인하지 못했다.
- 테스트 페이지에는 ‘테스트 시작되지 않음’으로 표시된다. 같은 페이지는 API 테스트 반영에 최대 24시간이 걸릴 수 있다고 안내하므로 실제 호출 미실행을 의미한다고 단정할 수 없다.
- 게시 페이지는 개인정보처리방침 URL을 요구하며 ‘게시’ 버튼은 비활성화되어 있다. 앱은 게시 전 단계로 보인다.
- 기본 설정의 개인정보처리방침 URL은 비어 있다. 서비스 약관 URL과 데이터 삭제 안내 URL은 모두 `https://www.facebook.com/`으로 등록되어 있어 todak 전용 안내가 아니다.
- 검색 0건의 원인을 위 설정만으로 확정할 수는 없다. 개인정보처리방침과 데이터 삭제 안내 등 실제 서비스에 맞는 게시 자료를 준비하고, 게시 및 권한 검수 요건을 충족한 후 공개 게시물·댓글 조회를 재검증해야 한다.

## 개인정보 안내 페이지 준비

- `/privacy`, `/data-deletion` 페이지 및 공통 하단 링크를 구현했다. 사용자 지정 문의 주소는 `netla@naver.com`, 운영자 표기는 ‘토닥 운영자’이다.
- 현재 데이터 흐름(브라우저의 월령·선호, 메모리의 위치, 카카오 길찾기 전송, 사용자 구분 없는 서버 공유 평가)에 맞춰 작성했다. 일반 이용자용 Threads 수집 기능을 제공 중이라고 표시하지 않았다.
- 프로덕션 빌드 성공. 빌드 산출물로 두 경로 HTTP 200, 제목·문의처·링크를 확인했다. 추천/이동시간 테스트 9개 및 기존 홈 렌더 테스트 1개 통과.
- 전체 타입 검사는 기존 Cloudflare 타입 선언 부재로 실패했다(`cloudflare:workers`, `Fetcher`, `D1Database`). 새 페이지 관련 타입 오류는 나오지 않았다.
- 로컬 미리보기는 기존 실행기가 지원하는 날짜(2026-05-22)보다 프로젝트 호환 날짜(2026-08-25)가 최신이어서 실행되지 않았다. 관련 없는 실행 설정·의존성 버전은 변경하지 않았다.
- 공개 배포와 Meta 앱 URL 등록은 아직 하지 않았다. Sites 연결은 공개 상태이며 로컬 프로젝트는 Cloudflare 직접 배포 설정도 보유한다. 배포 시 기존 운영 대상과 바인딩을 유지해야 한다.

## 검색 알고리즘 구현 및 실제 데이터 제약

- 사용자 목표: Threads에서 데이터를 찾고 보여주는 알고리즘 구현. 실제 공개 글 확보 및 표시 검증이 끝나기 전에는 완료로 보지 않는다.
- `lib/threads.mjs`: 입력 검증, 서버 측 Threads 검색(최대 50건), 출처 URL 검증, 검색어 일치 필터, 중복 제거, 나들이·이용 정보·최신성 가중치, 광고 문구 감점, 최신순/관련성순 및 최대 30건 표시.
- `/api/threads`, `/threads` 및 홈 진입 링크 구현. 오류·빈 결과·검색 중 상태를 구분하며 작성자·작성일·원문/댓글 링크를 제공한다. 댓글 자체는 아직 수집하지 않는다.
- 개인정보 안내에 현재 검색 기능의 처리 내용을 반영했다. 토큰·검색 결과·검색어는 DB에 저장하지 않으며 Meta 오류 메시지와 페이지 이동 URL을 그대로 클라이언트에 전달하지 않는다.
- 알고리즘/API 클라이언트 단위 테스트 15개, 빌드된 API·검색 화면·기존 홈 응답 테스트 3개 통과. 정상 데이터 테스트는 명시적인 가짜 응답을 사용하는 통합 테스트이며 실제 게시물 조회 성공의 증거는 아니다.
- 실제 토큰으로 빌드된 `/api/threads?q=하남` 호출: HTTP 200, 원본 0건, 표시 0건. 인증을 쿼리에도 추가한 진단에서도 0건. 실제 공개 데이터 조회 검증은 미완료다.
- Meta 검색 권한의 ‘앱 검수에 추가’를 눌렀을 때 기술 제공업체 전환·비즈니스 인증·액세스 인증을 요구하는 안내가 표시되었다. 전환은 되돌릴 수 없다는 안내가 있어 실행하지 않고 Go back으로 닫았다. 권한 검수 신청도 제출하지 않았다.
- 사용자가 사업자 없이 개인 계정만 있다고 확인했다. 개인정보처리방침 배포만으로 공개 검색 접근 문제를 해결할 수 있다고 판단하지 않는다.
- 대안 조사: SocialiQ는 별도 키로 Threads 공개 검색을 제공한다고 안내하며 가입 시 카드 없이 100회 무료 호출, 이후 종량제 $0.01/호출을 안내한다(https://socialiq.dev/platforms/threads , https://socialiq.dev/pricing). 실제 품질·작동 여부는 미검증이다. 가입·약관 동의·결제·키 발급은 하지 않았다. 기존 Meta 토큰을 이 업체에 보내지 않는다.
- Daum 웹검색도 검토했으나 로컬 카카오 키가 없고 공개 검색 도구에서는 관련 Threads 글을 확보하지 못했다. 제공되지 않는 실시간 데이터 대신 예시 글을 실제 결과로 표시하지 않는다.

## 최신 제약과 중단 지점

- 사용자가 ‘별도 검색은 하지마’라고 명시했다. SocialiQ 등 별도 검색 서비스의 가입·연결은 진행하지 않으며 기존 가입 질문도 더 이상 대기 항목이 아니다.
- 네트워크 제한 없이 빌드된 앱의 공식 검색 경로를 다시 확인했다: HTTP 200, sourceCount 0, displayedCount 0, realResultsVerified false.
- 공식 API의 실제 데이터 접근 제약이 연속된 목표 진행 턴에서 유지되었다. 개인 계정만 있고 Meta 검수에 필요한 비즈니스 인증을 진행할 수 없으며 외부 검색 서비스도 사용하지 않는다.
- 현재 구현과 검증 결과는 보존한다. 목표는 미완료이며 실제 공개 데이터를 앱이 자동으로 가져와 표시할 수 있는 연결 수단이 확보되어야 완료 검증을 재개할 수 있다. 로그인된 화면에서 사람이 확인한 글을 API 자동 조회 성공으로 대체하지 않는다.

## 개인용 브라우저 방식 구현

- 사용자가 ‘로그인된 내 브라우저에서 검색하고 화면의 글을 읽는 방식’을 시도하도록 요청했다.
- `extensions/threads-reader`에 개인용 Chrome 확장 프로그램을 구현했다. `activeTab`, `scripting`만 사용하며 상시 호스트 접근·쿠키·저장소 권한은 없다. 팝업의 외부 연결은 CSP로 차단했다.
- 현재 Threads 검색 화면의 DOM에서 글을 읽고 기존 정렬 알고리즘으로 팝업에 표시한다. 검색 화면 열기→결과 로딩→도구 클릭 순서로 동작하며 지속 자동 수집 서비스가 아니다. API 구현은 보존했다.
- 실제 화면에서 본문과 작성자를 구분하는 읽기 로직을 실행해 나들이 글 4건의 본문·작성자·원문·정확한 작성 시각을 확인했다. 직접 검색 UI가 사용하는 `serp_type=default`를 검색 링크에 반영했다.
- 확장 프로그램 권한 범위, 다른 사이트·메시지 페이지 거부, 정렬·안전한 텍스트 표시, 로딩·빈 화면 처리 테스트 4개 통과. 읽기 함수 실제 실행과 팝업 API 모사 테스트를 구분한다.
- 설치용 폴더: `work/threads-reader`. 재생성: `npm run build:threads-reader`.
- 사용자가 직접 설치를 완료했다. 2026-09-06 17:54 KST, 설치된 확장 프로그램을 Chrome 툴바에서 실행하여 ‘하남 아이랑’ 검색 화면의 실제 글 4건 읽기→관련성 정렬→팝업 표시를 확인했다. 작성자·날짜·일치 이유·원문 링크가 표시되었고 박물관·과학관 글이 일반 맛집 질문보다 앞섰다.
- 이 검증은 설치된 확장 프로그램의 실제 실행 결과다. 최신순 전환·다시 읽기·원문 링크 클릭의 설치 환경 검증은 브라우저 사용 중 화면 전환으로 완료하지 못했다. 해당 항목의 코드/모사 테스트와 실제 클릭 검증을 구분한다.
- 개인 브라우저에서 실제 데이터 읽기와 표시가 가능해졌으나 공개 사이트의 공식 API 0건 문제 및 서버 자동 수집 제약은 그대로다.
